# Reference Audit — Kuro Coffee Template (Phase 0)

- **Reference URL:** https://kuro-coffee-template.modulify.website/
- **Audit date:** 2026-11-24 (browser task 12:51–12:57 UTC, 5 min; text fetch 12:51 UTC)
- **Project:** `ela-coffee` — rebuild for Elahe Abdali (Tehran), bilingual fa/en, RTL-first
- **Licence status:** user states they hold a valid licence to use the template. No licence file/receipt was supplied in this phase — see §9 and `ASSETS.md`. No template source code was supplied; only exported assets (see §7).
- **Method:** live-browser crawl (all dialogs/states opened, one drink added to the bag to inspect the filled state, then cleared), `browser.open` text fetch, inspection of the user-supplied `theme.css.txt` (3,778 lines, compiled Tailwind v4 output), `svg_and_img.txt` (56 lines of exported HTML/SVG), and `Images.zip` / `fonts.zip` (font identification with fontTools, image dimensions with Pillow, MD5 dedup).

> Honest limits of this audit — read before Phase 1:
>
> 1. The browser tool used has **no viewport-resize control**, so its screenshots are all **1919×998 px (≈1920 desktop)**. The five required widths were therefore captured separately with a local Playwright **Firefox** install (Chromium downloads failed in this environment; the system Chromium is blocked by a Hatch WebGL policy). Those files exist and were visually checked — see §7. They are viewport shots (1000 px tall) of the hero only; full-page captures of the lower sections at each width are a Phase 1 follow-up.
> 2. No font-file URLs, network waterfall, or animation timings were observable from the live page with the available tooling. All animation values below come from the supplied compiled CSS, which is the authoritative source for them.
> 3. Filenames on the live site are `.jpg` under `/images/…` served via `/_next/image?w=3840&q=75`; the files supplied by the user are `.webp` re-exports with different dimensions. The mapping in §7 is therefore a **best-effort hypothesis to be confirmed in Phase 1** — do not treat it as verified.

## 1. Sitemap and page inventory

The reference is a **single-page site**. There is exactly one real route.

| Route                         | Result                                                                                                                                                                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                           | The whole site (all sections below, anchors `#hero #story #menu #process #origins #join`)                                                                                                                                           |
| `/menu`, `/about`, `/contact` | Branded 404: title `Page not found - Kuro`, heading `404`, body paraphrase: "This cup is empty… the page you were looking for has moved or never existed", button `Back to the flavors` → `/`. Header and footer remain on the 404. |
| Any other path                | Same branded 404 (verified pattern)                                                                                                                                                                                                 |

**Anchors (in-page navigation):** `#hero` (flavour wheel), `#story`, `#menu`, `#process`, `#origins`, `#join` (newsletter).

**External links:** exactly one — `Made with Modulify` → `https://modulify.ai/?ref=kuro-coffee.modulify.website` (footer, menu drawer, hero badge). **No** social links, address, opening hours, phone, map, or contact page exist anywhere on the reference. Those are additions for `ela-coffee` (Iranian contact channels, Neshan/Balad map), not a fidelity requirement.

**Coffee / Matcha is NOT a route.** It is client-side state (`html[data-brand=matcha]` in the CSS; the toggle never changes the URL and adds no query param). The two modes are two complete parallel sites sharing one layout — same anchors, different theme tokens, copy, prices, images and stats. This is the single most important architectural fact for the rebuild: one page component, two brand datasets.

### 3.5 Hero stage geometry (`.kuro-stage`, the heart of the page)

- `container-type: size`; `--s: min(100cqh, 137cqw)` on mobile; ≥640 px `--s: max(100cqh, 100cqw / 1.7917)` — i.e. the scene is sized to a **1.7917:1 (≈16:9)** frame.
- `--scene-w: s * 1.7917`; `--cup-cy: scene-top + s * .459`; `--wheel-r: s * 1.6` (landscape ≥640 px: `s * 2`); `--wheel-step: 10.5deg`; `--wheel-d1: wheel-r * .1822`; `--tile: s * .13` (landscape: `.19`); `--chip: clamp(3.25rem, s * .072, 4.5rem)`; `--chip-y` / `--label-y` / `--headline-top` are all derived from `--s` and `--scene-top` (see CSS lines ~2913–2952 for the exact formulae — reimplement them, do not eyeball).
- Scene mask: `linear-gradient(#0000 0%, #000 14%)` × `linear-gradient(90deg, #0000 0%, #000 5% 95%, #0000 100%)`, `mask-composite: intersect`.
- `.kuro-tile` transform (per flavour tile): `rotate(d * 10.5deg) translateY(-wheel-r - s*.3*near) scale(1 - .55*near)`, opacity fades with angular distance (`--d = var - rot - intro`). This is a **CSS custom-property wheel, not a JS 3D transform** — the rotation state lives in `--rot` / `--intro` (`@property --rot <number>`, `--intro <number>`).
- `.kuro-contours`: `repeating-radial-gradient(circle at 80% 120%, transparent 0 22px, crema 22px 23px)` (11% crema via `color-mix` where supported) — the faint contour rings behind sections.
- `.kuro-glass`: `isolation: isolate` with `::before/::after` overlays; `.kuro-glass-photo` is the image layer (`z-index: 1`).
