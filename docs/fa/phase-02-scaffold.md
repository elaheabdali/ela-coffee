# فاز ۲ — اسکافولد مونورپو و ابزارها

- **وضعیت:** انجام شد (۲۰۲۶-۱۱-۲۴)؛ فاز ۱ تایید شده بود و فاز ۲ با دستور تو شروع شد.
- **هدف این فاز:** ساختن اسکلت پروژه — مونورپو، ابزارها، توکن‌ها و پایهٔ موشن — بدون اینکه هنوز صفحهٔ واقعی یا چرخ طعم ساخته شود. همه‌چیز طوری چیده شده که فازهای بعد روی آن سوار شوند.

> اگر فقط می‌خواهی پروژه را اجرا کنی، برو سراغ بخش «اجرا» در پایین. بقیهٔ این سند توضیح می‌دهد هر چیزی چرا این‌طور ساخته شده است.

## ۱. ساختار مونورپو

```
ela-coffee/
  apps/web/                  # تنها اپلیکیشن (Next.js)
    src/app/[locale]/        # صفحه‌ها زیر /fa و /en
    src/i18n/                # routing / request / navigation (next-intl)
    src/proxy.ts             # مسیریابی زبان (جای middleware)
    src/components/          # کامپوننت‌های موقت صفحهٔ جایگزین
    public/images/           # عکس‌های تاییدشده (۲۴ فایل)
    public/fonts/            # ۳ فونت لاتین
  packages/
    ui/                      # دیزاین‌سیستم: Button ،Pill ،Price ،Reveal
    i18n/                    # دیکشنری fa/en + فرمت‌کننده‌ها
    config/                  # پیش‌فرض‌های مشترک TypeScript ،ESLint ،Prettier
  docs/  ASSETS.md  README.md  .env.example
```

**چرا مونورپو؟** چون دیزاین‌سیستم (`ui`) و ترجمه‌ها (`i18n`) باید مستقل از اپ تست و استفاده شوند؛ اگر فردا اپ دومی (مثلاً پنل مدیریت) اضافه شد، همین پکیج‌ها را بدون تغییر مصرف می‌کند. ولی عمداً «لاغر» نگهش داشتیم: لایهٔ دیتابیس و API جدا نشد، چون فعلاً فقط یک اپ مصرف‌کننده دارد (تصمیم معماری §۳.۲).

**چرا `workspace:*`؟** وابستگی‌های داخلی با پروتکل `workspace:*` نوشته شده‌اند؛ یعنی `apps/web` همیشه نسخهٔ همین ریپو از `@ela-coffee/ui` را می‌گیرد، نه نسخه‌ای از npm. این یعنی تغییر در `packages/ui` بلافاصله در اپ دیده می‌شود.

## ۳. چندزبانه (i18n) و راست‌به‌چپ

- مسیرها `/fa` (پیش‌فرض) و `/en` هستند. `/` به `/fa` می‌رود.
- ترجمه‌ها **دو جا تکرار نشده‌اند**: دیکشنری‌ها فقط در `packages/i18n/src/fa.ts` و `en.ts` زندگی می‌کنند و next-intl هم همان‌ها را می‌خواند (`src/i18n/request.ts`). پس ترجمهٔ صفحه و ترجمهٔ next-intl هیچ‌وقت از هم جدا نمی‌شوند.
- `html` برای `fa` می‌شود `lang="fa" dir="rtl"` و برای `en` می‌شود `lang="en" dir="ltr"`.
- تایپ‌چک کلیدهای ترجمه فعال است (`src/types/next-intl.d.ts`)؛ اگر کلیدی در دیکشنری نباشد، TypeScript خطا می‌دهد.

**قانون‌های حذف تکراری که اعمال شد:**

- تکراری‌های MD5 حذف شدند: `strawberry.webp` = `strawberry (1).webp`؛ `bean (1).webp` = `bean (2).webp`؛ `original (3).webp` = `original (4).webp`.
- هرجا نسخه‌های `(1)`/`(2)` با رزولوشن متفاوت بودند، **بزرگ‌تر** نگه داشته شد: صحنه‌های لاته از فایل‌های ۱۹۲۰×۱۰۷۲، `bean` از `bean (1).webp` (۱۱۳۳×۱۵۰۰)، و تصاویر مراحل از نسخه‌های ۶۴۰ پیکسلی.
- دو فایل `ingredients-key.jpg` و `ingredients-v2-key.jpg` (هر کدام ۱٫۳ تا ۱٫۵ مگابایت) فعلاً همان‌طور که هستند نگه داشته شده‌اند؛ **در فاز ۹ به AVIF/WebP تبدیل می‌شوند** و اول باید معلوم شود `v2` نسخهٔ ماچا است یا نه.

### چیزهایی که علاوه بر جدول رعایت شده

- **تاخیر آشکارشدن** با متغیر `--reveal-delay` کنترل می‌شود (مقادیر دیده‌شده در مرجع: ۳۰۰ / ۴۵۰ / ۶۰۰ میلی‌ثانیه). کامپوننت `Reveal` در `packages/ui` با IntersectionObserver، وقتی عنصر وارد دید شد، `data-revealed` را اضافه می‌کند.
- **اگر جاوااسکریپت نباشد، محتوا پنهان نمی‌ماند.** این باگِ مرجع بود (audit §۸.۷): در مرجع، اگر observer اجرا نمی‌شد محتوا برای همیشه نامرئی می‌ماند. اینجا `data-reveal` فقط از داخل `useEffect` اضافه می‌شود؛ پس بدون JS اصلاً صفتی نیست که چیزی را پنهان کند، و اگر مرورگر IntersectionObserver نداشت، محتوا فوراً آشکار می‌شود.
- **`html[data-motion=paused]`** انیمیشن‌های `float` و `marquee` و `scroll-cue` را متوقف می‌کند (دکمهٔ «توقف حرکت» در فاز ۴ وصل می‌شود).
- **`prefers-reduced-motion: reduce`** انیمیشن‌های چرخ، شناور، bump، pour، scroll-cue و marquee را کاملاً خاموش می‌کند و محتوای reveal را مستقیم نشان می‌دهد. اسکرول نرم هم فقط وقتی فعال است که کاربر کاهش حرکت نخواسته باشد.
- **تعویض برند (قهوه ↔ ماچا)** رنگ‌ها را در ۰٫۶ ثانیه عوض می‌کند، فقط وقتی `html[data-brand-switching]` ست شده باشد و فقط وقتی کاربر کاهش حرکت نخواسته باشد (audit §۳.۲). دکمهٔ تعویض در صفحهٔ جایگزین همین حالا کار می‌کند — بزن و ببین کل صفحه سبز می‌شود.
- **فوکوسِ visible:** مرجع حلقهٔ فوکوس نداشت (audit §۸.۶). اینجا `:focus-visible` یک outline دو پیکسلی به رنگ `--ring` دارد.
- **متغیرهای سفارشی ثبت‌شده:** `@property --rot` ،`--intro` ،`--pour` — وضعیت چرخ و ماسکِ pour در این متغیرها زندگی می‌کند، نه در استیت جاوااسکریپت.

### چرخ طعم کامل، هنوز ساخته نشده

هندسهٔ کامل چرخ (`.kuro-stage` — audit §۳.۵) در فاز ۴ پیاده می‌شود. برای اینکه چیزی جعل نشده باشد، خلاصهٔ فرمول‌ها به‌صورت کامنت در انتهای `globals.css` آمده است: `container-type: size`، `--s`، `--wheel-r: s * 1.6`، گام ۱۰٫۵ درجه، ماسک صحنه، و تبدیل `.kuro-tile`. در این فاز فقط انیمیشن ورود چرخ (`kuro-wheel-in`) و ماسک pour آماده‌اند.

## ۷. صفحهٔ جایگزین (placeholder)

صفحهٔ فعلی سایت واقعی نیست؛ فقط برای اینکه اسکافولد را بشود دید و لمس کرد. در `/fa` و `/en` این‌ها را نشان می‌دهد:

- دکمهٔ تعویض برند (قهوه/ماچا) که واقعاً تم را عوض می‌کند؛
- تیتر با انیمیشن کلمه‌به‌کلمه؛
- تصویر هیرو (`original.webp`) با انیمیشن ورود و ماسک pour؛
- نوار marquee با نام طعم‌ها، یک قطعهٔ شناور (`ingredients.webp`)، و شورون اسکرول؛
- یک بلوک `Reveal` با تاخیر ۳۰۰ میلی‌ثانیه؛
- قیمت نمونه با کامپوننت `Price`: **۱۸۰٬۰۰۰ تومان** — قیمت موقت از معماری §۱۴ (تو تایید کردی قیمت‌های رندوم/موقت اشکالی ندارد)؛
- یک دکمهٔ «افزودن به سبد» نمایشی با انیمیشن bump (سبد واقعی در فاز ۴ می‌آید)؛
- یادداشتی که می‌گوید چرخ کامل و بخش‌ها در فاز ۴ می‌آیند.

صفحهٔ ۴۰۴ هم برند شده است: «این فنجان خالی است…» / “This cup is empty…” با لینک بازگشت. دو نکتهٔ فنی که در ساختش معلوم شد: (۱) در Next.js 16 به `not-found.tsx` هیچ `params` داده نمی‌شود، پس زبان را با `getLocale()` از next-intl می‌خوانیم؛ (۲) برای آدرس‌هایی که اصلاً روتی ندارند (مثلاً `/fa/xyz`)، Next به `global-not-found.tsx` نیاز دارد (قابلیت آزمایشی `experimental.globalNotFound`) — آن را هم اضافه کردیم، با هر دو زبان داخل خودش، چون آن صفحه بیرون از layoutها رندر می‌شود و به ترجمه‌ها دسترسی ندارد.

## ۸. ابزارها و کیفیت

- **ESLint** (flat config) با پیش‌فرض مشترک در `packages/config/eslint`؛ **Prettier** با `singleQuote: false` (دابل‌کوت، هماهنگ با اکوسیستم Next.js)، `trailingComma: "all"` (دیف‌های تمیزتر)، `printWidth: 100` (کمی بازتر از ۸۰ تا کلاس‌های بلند Tailwind کمتر بشکنند). تنظیمات Prettier در `packages/config/prettier/index.json` است و `package.json` ریشه با `"prettier": "@ela-coffee/config/prettier"` به آن اشاره می‌کند.
- **Husky + lint-staged + Commitlint:** قبل از هر کامیت، فایل‌های stageشده با ESLint و Prettier چک می‌شوند و پیام کامیت باید Conventional باشد (`feat: ...` ،`fix: ...`).
- **CI (GitHub Actions):** در `.github/workflows/ci.yml` — نصب با `--frozen-lockfile`، بعد `typecheck`، `lint`، `test`، `build`. جاب Playwright فعلاً فقط یک `echo` است و صریحاً نوشته شده که در فاز ۱۰ واقعی می‌شود؛ این را پنهان نکردیم.
- **تست‌ها:** ۱۴ تست در ۴ فایل — فرمت‌کننده‌های i18n (۹ تست)، Button (۳ تست)، Reveal (۱ تست)، و رندر صفحهٔ جایگزین (۱ تست). همه سبزند.

## ۹. اجرا

```bash
cd ~/workspace/ela-coffee

pnpm install            # نصب (lockfile قفل‌شده)
pnpm dev                # اجرای dev سرور → http://localhost:3000/fa
pnpm typecheck          # tsc --noEmit در هر سه پکیج
pnpm lint               # ESLint روی کل ریپو
pnpm test               # Vitest (یک‌بار)
pnpm test:watch         # Vitest در حالت watch
pnpm build              # بیلد production
pnpm format             # فرمت همهٔ فایل‌ها با Prettier
```

**نکتهٔ محیطی (مهم):** فایل‌سیستم این ماشین `chown` را قبول نمی‌کند و pnpm هنگام بازنویسی `pnpm-lock.yaml` موجود، روی `chown` خطای `EPERM` می‌دهد. راه‌حل: اگر `pnpm install` یا `pnpm add` با این خطا شکست خورد، `pnpm-lock.yaml` را حذف و `pnpm install` را دوباره اجرا کن تا lockfile از اول ساخته شود. (خطای `EPERM` روی `node_modules/.pnpm/lock.yaml` بی‌خطر است و نصب را خراب نمی‌کند.) روی ماشین تو این مشکل وجود ندارد؛ فقط مخصوص این محیط است.
