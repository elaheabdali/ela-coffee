## ۱. قبل از تحویل — چیزهایی که فقط صاحب پروژه / مشتری باید بدهد یا انجام بدهد

| # | مورد | چرا لازم است | چطور انجام می‌شود |
|---|------|-------------|------------------|
| ۱ | **پروژهٔ Neon و `DATABASE_URL`** | بدون آن، سایت دیتابیس واقعی ندارد: سفارش‌ها، رزروها و عضویت خبرنامه فقط در حافظهٔ موقت سرور زنده‌اند و **با هر دیپلوی یا ری‌استارت ورسل پاک می‌شوند**. این برای دمو قابل‌قبول است، برای مشتری نه. | قدم‌به‌قدم در `docs/fa/phase-06-backend.md` بخش ۹ و `docs/fa/phase-11-deploy.md` بخش ۹. خلاصه: ساخت پروژهٔ رایگان در neon.tech → کپی رشتهٔ اتصال → گذاشتن `DATABASE_URL` در ورسل (Settings → Environment Variables، محیط‌های Production و Preview) → Redeploy → اجرای `pnpm --filter web db:migrate` و `pnpm --filter web db:seed` از ترمینال خودت (با `DATABASE_URL` در `apps/web/.env.local`). بعدش یک سفارش آزمایشی ثبت کن و در داشبورد Neon ببین جدول `Order` پر شده؛ اگر خالی ماند، یعنی `DATABASE_URL` نرسیده و برنامه بی‌صدا برگشته به fallback. |
| ۲ | **شناسهٔ merchant سندباکس زرین‌پال** | پرداخت الان روی Mock است: هیچ پول واقعی جابه‌جا نمی‌شود و سفارش‌ها بلافاصله PAID می‌شوند. برای تست واقعی پرداخت، `PAYMENT_PROVIDER=zarinpal` و `ZARINPAL_MERCHANT_ID` لازم است. توجه: در نسخهٔ ۱، callback زرین‌پال ساخته نشده — پرداخت در حالت زرین‌پال در وضعیت PENDING می‌ماند. | شناسه را از پنل سندباکس زرین‌پال بگیر و فقط در داشبورد ورسل بگذار (هرگز در گیت، چت یا فایل ننویس). بعد `PAYMENT_PROVIDER` را هم در ورسل روی `zarinpal` بگذار و Redeploy کن. |
| ۳ | **اطلاعات تماس واقعی فوتر** | الان در فوتر شمارهٔ `۰۲۱ ۰۰۰۰ ۰۰۰۰` و آدرس‌های `t.me/elacoffee` ،`eitaa.com/elacoffee` ،`instagram.com/elacoffee` هست — همه جای‌نگه‌دارند و به جایی نمی‌رسند. | شمارهٔ واقعی، هندل تلگرام/ایتا/اینستاگرام و (اگر هست) واتساپ را بده تا در `apps/web/src/components/SiteFooter.tsx` جایگزین شوند. |
| ۴ | **بازبینی ۳۲ ترجمهٔ فارسی `TODO(review)`** | ⚠️ **فوری و قابل‌مشاهده برای بازدیدکننده:** عبارت `— TODO(review)` همین حالا داخل متن‌های فارسی است و روی کارت‌های منو و دیالوگ طعم‌ها در نسخهٔ فارسی دیده می‌شود. تا وقتی پاک نشود، سایت قابل‌تحویل نیست. | برگهٔ بازبینی جداگانه تحویل داده شده (`ela-coffee-translation-review.md`): برای هر مورد یا «تایید» بفرست یا متن اصلاح‌شده‌ات را. بعد از تایید هر مورد، پرچم از آن رشته در `apps/web/src/data/flavours.ts` برداشته می‌شود **و** تست شمارنده در `apps/web/src/data/flavours.test.ts` خط ۵۳ (که دقیقاً ۳۲ پرچم را enforced می‌کند) به‌روز می‌شود. نکتهٔ ری‌برند: در فاز ۱۲ برند از کورو به الا تغییر کرد؛ از ۳۲ مورد برگه، فقط **مورد ۱۷** (معرفی منوی قهوه، خط ۴۴۲ — «اسپرسوی کورو» ← «اسپرسوی الا») متن واقعی‌اش عوض شد و سربرگ ۱۵ مورد دیگر (۱ تا ۶، ۱۳، ۱۴، ۱۹ تا ۲۲، ۲۷ تا ۲۹) برچسب «کورو (قهوه)» به «الا (قهوه)» تغییر کرد. |
| ۵ | **قیمت‌های واقعی تومانی** | قیمت‌های فعلی (۱۸۰٬۰۰۰ تا ۲۱۰٬۰۰۰ تومان) جای‌نگه‌دار و تصادفی‌اند — با تایید خودت برای نمونه قابل‌قبول بود، ولی برای تحویل باید واقعی شوند. | قیمت هر ۱۲ نوشیدنی را بده؛ در `apps/web/src/data/flavours.ts` (فیلد `priceToman`) جایگزین می‌شوند. قیمت در JSON-LD و همه‌جا از همان یک فایل خوانده می‌شود، پس یک‌جا عوض می‌شود. |
| ۶ | **مدرک لایسنس تمپلیت** | هنوز هیچ رسید یا فایلی که استفادهٔ مجدد از عکس‌ها و فونت‌های تمپلیت را پوشش بدهد، تحویل داده نشده (باز از فاز ۰). ریپو با انتخاب صریح تو **عمومی** است، پس این مدرک مهم‌تر هم شده. | رسید خرید/لایسنس تمپلیت را نگه دار و (در صورت نیاز) در `ASSETS.md` ثبتش کن. تا وقتی نرسیده، با مشتری دربارهٔ منشأ عکس‌ها و فونت‌ها شفاف باش. |
| ۷ | **عکس‌های واقعی ماچا** | دو جای‌نگه‌دار تصویری هست: صحنهٔ «میدوری اورجینال» و قدم «آسیاب سنگی» در بخش طرز تهیه، هر دو فعلاً `tea.webp` را نشان می‌دهند (`imagePlaceholder: true` در `flavours.ts` خط ۵۸۴). | عکس‌های واقعی را بده تا جایگزین `tea.webp` شوند و پرچم `imagePlaceholder` برداشته شود. |

## ۲. اجرای لوکال (روی کامپیوتر خودت)

```bash
cd ~/workspace/ela-coffee
pnpm install            # نصب (نسخهٔ pnpm: 10.34.9؛ اگر pnpm پیدا نشد: npm install -g pnpm@10.34.9)
cp .env.example apps/web/.env.local   # بعد مقدارها را پر کن (بخش ۴)
pnpm dev                # → http://localhost:3000/fa
```

| دستور | چه می‌کند |
|---|---|
| `pnpm typecheck` | تایپ‌چک همهٔ پکیج‌ها |
| `pnpm lint` | ESLint (۱ هشدار از قبل در ReservationForm — یادداشت React Compiler از فاز ۶ — خطا نیست) |
| `pnpm test` | تست واحد Vitest — **۲۲۵ تست در ۳۰ فایل** |
| `pnpm test:e2e` (در `apps/web`) | تست E2E با Playwright — **۵۸ تست** (۴۸ عملکردی + ۱۰ بصری) |
| `pnpm build` | بیلد پروداکشن |
| `pnpm --filter web db:migrate` / `db:seed` | مایگریشن و سید دیتابیس (فقط با `DATABASE_URL`) |

نکتهٔ محیطی: نصب `pnpm` گاهی با خطای `EPERM` روی chown فایل قفل
می‌افتد (باگ شناخته‌شدهٔ این محیط)؛ راه‌حل: `rm pnpm-lock.yaml &&
pnpm install`. دستور `pnpm audit` لوکال کار نمی‌کند (registry جلویش
را می‌گیرد) — در CI اجرا می‌شود، لوکال اجراش نکن.

## ۳. دیپلوی — چطور کار می‌کند

- **هر پوش به `master` → دیپلوی Production** در ورسل، به‌صورت خودکار.
  آدرس: **https://ela-coffee-yi88.vercel.app**
- **هر پوش به شاخهٔ دیگر یا هر PR → دیپلوی Preview** با آدرس تصادفی،
  برای تست قبل از مرج.
- **قانون:** روی کامیت قرمز دیپلوی نکن — اول در تب Actions گیت‌هاب
  سبز بودن CI را ببین (دو جاب: `check` و `e2e`).

### برگرداندن به نسخهٔ قبل (Rollback در ورسل)

داشبورد ورسل → پروژهٔ `ela-coffee-yi88` → تب **Deployments** → روی
دیپلوی سالمِ قبلی، منوی `⋯` → **Redeploy** (یا **Promote to
Production** روی همان دیپلوی). هیچ دستوری در ترمینال لازم نیست؛
ورسل همان کامیت قبلی را دوباره بالا می‌آورد.

## ۴. متغیرهای محیطی — جدول کامل

در داشبورد ورسل: **Settings → Environment Variables**. مقدارها را فقط
آنجا بگذار — **هرگز** در گیت کامیت نکن، در چت نفرست، در فایل ننویس.

| متغیر | مقدار فعلی در ورسل | توضیح |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://ela-coffee-yi88.vercel.app` | آدرس پروداکشن؛ canonical، hreflang، sitemap و OG از همین ساخته می‌شوند. پیش‌فرض کد هم همین آدرس است — اگر دامنه عوض شد، هر دو را با هم عوض کن. |
| `DATABASE_URL` | **ست نشده** | رشتهٔ اتصال Neon (شکل: `postgresql://user:password@host/db?sslmode=require`). تا ست نشود، fallback حافظهٔ موقت فعال است (بخش ۵). |
| `PAYMENT_PROVIDER` | **ست نشده → پیش‌فرض `mock`** | `mock` (بدون پول واقعی) یا `zarinpal` (سندباکس). |
| `ZARINPAL_MERCHANT_ID` | **ست نشده** | فقط وقتی `PAYMENT_PROVIDER=zarinpal` باشد خوانده می‌شود. |

بعد از تغییر هر متغیر، **Redeploy** لازم است (Deployments → `⋯` →
Redeploy) — بدون آن، مقدار جدید به سرور نمی‌رسد. برای لوکال، همین
متغیرها را در `apps/web/.env.local` بگذار (فایل نمونه: `.env.example`
در ریشهٔ ریپو).

## ۵. ⚠️ هشدار مهم: تا وقتی Neon نیست، دیتابیس واقعی نداری

بدون `DATABASE_URL`، برنامه از **seed-JSON + حافظهٔ موقت داخل سرور**
استفاده می‌کند (`apps/web/src/lib/store.ts`): منو همان ۱۲ نوشیدنیِ
فایل seed است و سفارش/رزرو/خبرنامه فقط تا وقتی سرور ری‌استارت نشده
زنده‌اند. روی ورسل یعنی: **با هر دیپلوی جدید (و هر بار که ورسل سرور را
خاموش و روشن کند)، همهٔ سفارش‌ها و رزروهای ثبت‌شده پاک می‌شوند.**
هرگز با مشتری طوری رفتار نکن که انگار سفارش‌ها ماندگارند، تا وقتی
Neon وصل نشده.

## ۶. چیزهایی که باید بدانی (وضعیت فعلی)

  تغییر کرد — همه‌جا: نام‌ها، عنوان‌ها، `data-brand="ela"`، شناسهٔ
  نوشیدنی‌ها (`ela-original` …)، هندل‌های فوتر (`elacoffee`). برند
  ماچا **میدوری (Midori)** دست نخورده. یک استثنای داخلی: مقدار enum
  دیتابیس در Postgres هنوز `KURO` است (فقط برچسب ذخیره‌سازی، هیچ‌وقت
  دیده نمی‌شود) — توضیح کامل در `docs/architecture.md` §۷. عنوان
  داستان قهوه هم بازنویسی شد: «Ela starts black. The rest is up to
  you.» / «الا سیاه شروع می‌شود. بقیه‌اش با توست.» (قبلاً «Kuro means
  black» بود که برای «الا» درست نبود).
